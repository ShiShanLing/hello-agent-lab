# Hello Agent Lab · Agent 开发经历

> 独立设计并实现一套可部署的 AI Agent 学习与演示系统：模型负责决策，工程负责执行；覆盖工具调用、RAG、MCP、多 Agent 协作、工作流、评测与运维发布。

---

## 一、项目概述

**项目名称**：Hello Agent Lab  
**角色**：全栈 / Agent 工程（独立开发）  
**定位**：从最小命令行 Agent 演进为「后端 API + 多前端 + 任务队列 + 知识库 + 管理后台」的完整练习平台，可在自有服务器稳定运行。

**核心思路**：DeepSeek（OpenAI 兼容）负责判断是否调用工具及参数；Python 负责安全执行工具并把结果回灌上下文，形成标准 Agent 循环。

---

## 二、主要功能

### 1. Agent 核心能力
- **Tool Calling 循环**：计算、沙箱 Python、Todo、天气、知识检索、联网兜底等
- **人机确认（HITL）**：完成 Todo、OpenAPI 写操作等需用户二次确认；多 Agent 协作在「规划完成后」暂停，确认后再执行
- **多模型路由**：简单任务走 cheap、复杂任务走 strong，失败可降级
- **工具结果 Offload**：超长工具结果外置存储，上下文只留摘要 + `ref`，按需取回
- **Skills**：按需加载工作说明书，扩展 Agent 行为说明而不膨胀系统提示

### 2. 知识与检索（RAG）
- 用户知识库上传：Markdown / TXT / PDF / Word
- 关键词 + 向量混合检索（`fastembed` + `sqlite-vec`）
- 知识不足时联网搜索摘要兜底，并要求标注来源
- 会话级聊天附件：文本抽取；扫描件 PDF / 图片走本地 Tesseract OCR

### 3. 扩展与集成
- **MCP**：独立天气 / 知识库 Server，可配置远程 SSE/HTTP MCP
- **OpenAPI → 工具**：粘贴 OpenAPI JSON，勾选接口后动态生成可调用工具；SSRF 防护；写操作需确认
- **长期记忆**：偏好 / 事实 / 目标 / 约束跨会话注入
- **每日 Todo 简报**：可选定时任务（默认关闭）

### 4. 多 Agent 与工作流
- **多 Agent 协作**：规划 → 人机确认计划 → 执行（真实调工具）→ 审核（可打回）
- **自动路由**：复杂目标自动进协作；「计算 + 记 Todo」等短组合保持单 Agent
- **可视化工作流**：异步执行、进度、取消 / 重试 / 审批节点、站内通知

### 5. 评测、观测与运维
- 评测中心：关键词 / 精确匹配 / LLM Judge、可信度、失败原因、基线对比、导出
- 运行观测：Token、费用估算、步骤轨迹、成功率等聚合指标
- 三前端独立站点：主站 / Todo / 管理后台（MFA）
- 一键发布脚本：测试、构建校验、备份、安全 `rsync`、健康检查与回滚

## 四、技术难点与攻克方式

### 1. Agent 上下文膨胀与长工具结果
**难点**：多轮工具调用（MCP / OpenAPI / 代码输出）易撑爆上下文，简单截断会丢关键信息。  
**做法**：引入工具结果 Offload——超过阈值的结果写入 SQLite，上下文只保留摘要与 `ref`；需要细节时再调用 `fetch_tool_result`。在「不丢信息」与「省 Token」之间取得平衡。

### 2. 多 Agent「看起来会干活」vs「真的调了工具」
**难点**：规划 / 执行 / 审核三角色容易退化成纯文案接力，执行角色编造工具结果。  
**做法**：
- 给规划 Agent 注入真实工具目录，禁止发明工具名；
- 执行角色使用可调工具集，并在审核规则中要求「缺工具证据必须打回」；
- 高风险写操作从协作工具集中排除，避免「替用户确认」。

### 3. 协作中的人机确认与长连接
**难点**：SSE 流式请求不能阻塞等待用户点击；若直接在请求里挂起，锁与超时都会出问题。  
**做法**：参考工作流 `waiting_approval` 模式——规划结束后持久化 `collaboration_runs` 检查点并结束本轮流；用户确认后走 `approve` 接口再开 SSE 续跑执行与审核。

### 4. 工具生态扩展与安全边界
**难点**：用户粘贴任意 OpenAPI / 接入远程 MCP 时，存在 SSRF、误调写接口、内网探测风险。  
**做法**：校验公网可达 URL、拒绝内网地址；写操作进入确认门闩；远程 MCP 探活与错误隔离；工具名动态注册但不扩大权限默认面。

### 5. RAG 可信度与「有没有依据」
**难点**：模型易在知识库未命中时编造答案。  
**做法**：自动优先检索本地知识；未命中再联网兜底；回答要求标注来源；评测侧用 LLM Judge + 可信度与失败原因，把「幻觉 / 漏工具」变成可回归问题。

### 6. 扫描件与图片进 Agent
**难点**：文字版 PDF 可直接抽文本，扫描件 / 图片没有文字层。  
**做法**：先文本抽取，空结果再本地 Tesseract OCR（中英）；限制页数与体积；与知识库上传路径分离（会话附件不入向量库），控制成本与隐私（数据不出机）。

### 7. 多应用同域部署的「误删兄弟站点」
**难点**：主站、`/todo/`、`/admin/` 共享父目录，错误的 `rsync --delete` 会删掉兄弟应用。  
**做法**：将发布红线写入 `AGENTS.md`；发布脚本强制排除 `todo/`、`admin/`；发布后四端健康检查；失败可回滚快照。

### 8. 流式体验与服务重启
**难点**：对话 SSE 长连接导致 systemd 停服卡在 deactivating，健康检查 502。  
**做法**：发布流程对 API 进程使用可控强杀后拉起，并轮询 `/health` 直至恢复，避免「发了但半死不活」。

## 五、架构要点（可写在简历补充说明）

```text
用户（主站 / Todo / Admin）
        │
     Nginx（静态 + /agent/api 反代）
        │
   FastAPI Agent API ── SSE 流式对话 / 协作 / 工作流
        │
   ┌────┼────┬──────────┬─────────┐
   │    │    │          │         │
 DeepSeek  工具层   SQLite     Redis/RQ
           │        （对话/Todo/   Worker
        本地工具    记忆/Offload/  （索引/评测/
        MCP/OpenAPI 附件/协作检查点） 工作流）
           │
        知识库文件 + OCR + 向量表
```

**工程原则**：模型做决策，代码做执行与安全边界；可观测、可评测、可发布，而不是只做「能聊的 Demo」。
