# AI Agent 入门笔记

## Agent 的基本组成

一个最小 AI Agent 通常由大语言模型、工具、记忆和执行循环组成。大语言模型负责理解目标和选择下一步行动，Python 程序负责真正执行工具。

## Tool Calling

Tool Calling 是模型输出结构化工具名称和参数的机制。模型不会亲自查询天气或写数据库，而是请求程序调用对应工具，程序再把工具结果放回对话上下文。

## MCP

MCP（Model Context Protocol）是一套连接 AI 应用与外部工具、资源的标准协议。MCP Client 负责连接服务和调用能力，MCP Server 负责公开工具。本项目的天气和本地知识库是两个独立 MCP Server；也可以在网页中添加远程 SSE / HTTP MCP。

## OpenAPI → 工具

OpenAPI（或 Swagger）用一份机器可读的接口说明书描述 HTTP API。本项目支持粘贴 OpenAPI JSON，自动把勾选的操作变成 Agent 可调用的工具：程序负责拼 URL、传参和鉴权，模型只负责选择工具与参数。写操作通常需要用户确认；内网地址会被拒绝，避免 SSRF。

## 工具结果 Offload（上下文卸载）

工具结果会占用模型上下文。若每次把完整 MCP / OpenAPI / 代码输出塞回对话，长任务很容易挤掉目标和约束。Offload 的做法是：大结果全文外置保存，上下文只留摘要和引用 `ref`；需要细节时再调用 `fetch_tool_result`。这比不可逆截断更安全，也比“永远全量塞进窗口”更省 Token。

## 聊天附件与 OCR

会话附件适合临时分析一份文档：文字层 PDF 直接抽取；扫描件与图片用**本地 Tesseract**（`chi_sim+eng`）OCR，数据不出机、无按次费用。OCR 不是 100% 准确，尤其是手写或低清晰度材料。本项目优先自托管 Tesseract，而不是默认云 OCR：运维成本可控，也符合现有 Baidu BCC 部署。若日后需要更高中文准确率，可再加可选云 OCR，而不替换这条默认路径。

## 长期记忆

长期记忆跨会话保存用户的稳定偏好、事实、目标和约束，与本会话聊天记录、知识库文档是三类不同信息。回答前程序会检索相关记忆并注入提示；用户也可以显式要求记住或忘记。

## 多模型路由

同一产品里可以把任务分成 cheap / strong 等角色：简单或高频任务用更小更快的模型，复杂推理用更强模型，并配置失败降级链。目标是在效果可接受的前提下降低成本和延迟。

## 多 Agent 协作

复杂目标可以拆成规划、执行、审核三个角色。规划完成后会先等人确认计划，再进入执行。执行角色应真实调用工具（计算、天气、Todo、知识库等），而不是只写一段看起来像结果的文字；需要用户确认的写操作仍应留给用户。审核角色负责发现「该用工具却没用」的问题并打回。

系统也可自动判断：简单的单轮工具题继续走普通对话；明确的多阶段方案、先规划再执行、或用户点名多智能体时，才进入协作流水线。

## RAG

RAG 是检索增强生成。程序先从外部知识库检索与问题相关的资料片段，再让大语言模型根据这些片段回答。这样可以使用模型训练数据之外的私有资料，并减少没有依据的编造。本项目还会在本地知识不足时用联网搜索摘要兜底，并要求标注来源。
